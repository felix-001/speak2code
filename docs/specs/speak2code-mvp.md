# Speak2Code MVP 产品与技术规格

- 状态：Draft
- 版本：0.1
- 日期：2026-10-23
- 依据：`README.md`、`design/architecture.md`、`prototypes/index.html`

## 1. 目标

Speak2Code 让用户通过手机或 Pad 浏览器，用自然语言描述一次编码需求，由灵矽理解并编排任务，调用 MCP Server 将任务交给本地编码 Agent，在用户授权的本地工作区中完成代码修改和验证，最后由用户检查差异并确认合并。

MVP 的核心价值不是自动合并，而是提供一条可追踪、可审查、可撤销的“语音/文字需求到本地代码变更”链路。

## 2. 当前现状与规格边界

### 2.1 当前已存在

- 可直接打开的静态 HTML 交互原型。
- 文字需求输入和演示任务。
- 浏览器录音、录音回放和浏览器原生语音识别（取决于浏览器）。
- Codex / Claude 选择交互。
- 接收需求、端侧编码、等待合并、已合并的模拟时间线。
- 原始代码与修改后代码的模拟差异展示。
- 基础键盘可访问性、重置任务和合并确认交互。

### 2.2 当前不存在

以下能力不应在真实服务接入前被视为已实现：

- 灵矽会话、MCP Server、网页和本地 Agent 的真实连接。
- 真实文件修改、补丁应用、测试执行和 Git 合并。
- 认证、授权、断线重试和任务持久化。
- 多任务并发、多人协作、历史记录和生产部署。
- 真实屏幕采集、网页观看和 AirPlay 等投屏能力。

### 2.3 MVP 范围

MVP 只支持以下组合：

- 一个用户会话。
- 一个已授权工作区。
- 一次只运行一个编码任务。
- 一个任务只修改一个工作分支或临时变更集。
- 一个用户在查看差异和验证结果后显式确认合并。
- 文字输入为必选兜底，语音输入为增强能力。

## 3. 用户与核心场景

### 3.1 目标用户

正在本地开发环境中工作的个人开发者。用户可以离开电脑，通过手机或 Pad 提交短小、边界清晰的代码修改，并在合并前查看结果。

### 3.2 主流程

1. 用户打开 MCP Server 提供的网页。
2. 网页展示当前连接状态和已授权工作区。
3. 用户输入文字，或授权麦克风后录音并确认识别文本。
4. 用户提交需求，服务端创建 `task_id`。
5. 灵矽补充必要上下文并调用已注册的 MCP 工具。
6. MCP Server 将任务交给选定的本地编码 Agent。
7. Agent 读取允许范围内的代码，生成补丁并运行配置允许的验证命令。
8. 网页通过事件流展示阶段、日志摘要、变更文件和验证结果。
9. 任务进入 `awaiting_confirmation`，用户查看差异。
10. 用户确认后才执行合并；取消或拒绝则保留原分支不变。

### 3.3 非目标

- 不以自然语言直接执行任意 shell 命令。
- 不允许 Agent 在未授权工作区之外读写文件。
- 不在用户未确认时修改默认分支。
- 不把网页观看画面等同于 AirPlay 接收。
- 不承诺所有浏览器都支持麦克风或语音识别。

## 4. 系统边界与职责

| 组件 | 必须负责 | 不负责 |
| --- | --- | --- |
| 手机 / Pad 浏览器 | 输入需求、授权麦克风、查看状态、审查差异、确认或拒绝 | 直接访问本地仓库、执行代码 |
| Web Server | 提供网页、维护浏览器会话、转发任务和事件 | 理解用户需求、绕过授权执行任务 |
| MCP Server | 向灵矽注册工具、校验工具调用、调用本地 Agent、汇总结果 | 代替用户做最终合并决定 |
| 灵矽 | 理解需求、补充上下文、编排工具调用 | 直接越过 MCP Server 访问工作区 |
| 本地编码 Agent | 在授权工作区内读写代码、生成补丁、运行允许的验证 | 访问工作区之外的路径、直接发布生产变更 |
| 本地工作区 | 保存真实代码、分支、补丁和验证结果 | 自行接受未经确认的变更 |
| 画面 / 投屏模块 | 在用户授权后采集当前工作画面、网页观看、发现和控制接收端投屏 | 决定代码任务状态或代替任务事件链路 |

代码任务链路与画面链路相互独立。MCP Server 负责画面获取和投屏控制；端侧环境只提供画面来源。网页观看画面不表示已经启动外部投屏。

## 5. 功能规格

### 5.1 会话与工作区

- 页面加载后显示服务连接状态、当前工作区名称和连接错误。
- 服务端为浏览器会话分配短期 `session_id`，不得将凭据放在 URL 中。
- 工作区必须由本地端显式注册并授权，服务端保存规范化绝对路径和允许操作范围。
- 同一工作区同一时刻最多有一个运行中的任务；冲突时返回可读错误，不覆盖已有任务。
- 服务重启或连接丢失后，页面显示状态未知，不能把任务自动显示为成功。

### 5.2 输入与语音

- 文字输入不能为空，长度上限由服务端校验，建议初始上限为 4,000 个字符。
- 录音前必须请求浏览器麦克风权限，并提供拒绝后的文字输入路径。
- 语音识别结果在发送前必须允许用户编辑和确认。
- 音频文件只作为可选的本地回放数据，不默认上传原始音频。
- 语音识别不可用、权限拒绝或识别失败时，不影响文字任务提交。

### 5.3 Agent 选择与执行

- MVP 支持 `codex` 和 `claude` 两个逻辑 Agent 类型。
- Agent 类型必须由服务端白名单校验，网页传入未知值时拒绝任务。
- Agent 执行前生成任务工作分支或隔离变更集，不直接写入默认分支。
- 每次工具调用记录开始时间、结束时间、阶段、退出码和脱敏错误摘要。
- 命令执行必须使用服务端配置的允许列表或固定测试入口；禁止把用户文本直接拼接为 shell 命令。
- 超时、取消、权限拒绝和 Agent 崩溃都必须进入明确的失败状态，并保留已有日志和补丁。

### 5.4 差异、验证与确认

- 服务端返回变更文件列表、统一 diff、增删行数和文件状态。
- 默认隐藏完整敏感文件内容；凭据、密钥和环境文件必须脱敏或禁止展示。
- 验证结果至少包含命令标识、退出码、开始/结束时间、摘要和日志位置。
- 只有在补丁生成完成后，任务才能进入 `awaiting_confirmation`。
- 验证失败时允许用户查看失败摘要，但默认不允许合并；如未来支持强制合并，必须单独授权并留下审计记录。
- 用户确认合并前，页面必须明确显示目标分支、变更文件数和验证状态。
- 合并失败不应丢失补丁，任务进入 `merge_failed`，允许重试或放弃。

### 5.5 任务取消与重置

- 用户可在任务执行中请求取消。
- 取消应停止后续 Agent 操作，并等待当前安全边界结束；不能粗暴删除工作区文件。
- 取消后保留任务事件和未合并变更，状态为 `cancelled`。
- 页面重置只清理当前浏览器视图，不得删除服务端任务、分支或审计记录。

### 5.6 画面观看与投屏（后续能力）

- 用户必须分别授权“网页观看”和“外部投屏”。
- 画面会话需要独立的 `screen_session_id`，不能复用代码任务的确认状态。
- MCP Server 负责接收画面源、向网页提供受控观看流，以及发现和控制 AirPlay 等接收端。
- 画面流必须绑定会话和允许设备，断开任务会话后不得继续公开画面。
- MVP 第一阶段只定义接口和权限边界，不要求实现画面编码、协议适配或录制。

## 6. 任务状态机

```text
idle
  -> queued
  -> understanding
  -> executing
  -> validating
  -> awaiting_confirmation
  -> merging
  -> completed
```

异常和用户动作可以从以下状态转出：

- `queued | understanding | executing | validating -> cancelling -> cancelled`
- `queued | understanding | executing | validating -> failed`
- `awaiting_confirmation -> rejected`
- `merging -> merge_failed`

约束：

- 状态只能由服务端推进，客户端只发送命令请求。
- 每次状态变化都产生单调递增的 `event_seq`。
- `completed` 只能在合并操作成功且目标分支状态已确认后产生。
- 断线重连后，客户端使用 `last_event_seq` 补拉事件，不根据本地计时器猜测状态。

## 7. 任务协议草案

### 7.1 创建任务

`POST /api/v1/tasks`

```json
{
  "workspace_id": "workspace_123",
  "agent": "codex",
  "request": "给提交按钮增加 loading 状态，并在提交时禁止重复点击",
  "input_type": "text",
  "base_ref": "main"
}
```

响应：

```json
{
  "task_id": "task_123",
  "session_id": "session_123",
  "status": "queued",
  "created_at": "2026-10-23T10:00:00Z"
}
```

### 7.2 任务事件

`GET /api/v1/tasks/{task_id}/events`，MVP 建议使用 Server-Sent Events。

事件统一包含：

```json
{
  "task_id": "task_123",
  "event_seq": 7,
  "type": "validation_finished",
  "occurred_at": "2026-10-23T10:01:20Z",
  "data": {}
}
```

事件类型至少包括：

- `task_created`
- `status_changed`
- `assistant_message`
- `agent_started`
- `file_changed`
- `validation_started`
- `validation_finished`
- `diff_ready`
- `confirmation_required`
- `merge_finished`
- `task_failed`
- `task_cancelled`

### 7.3 确认、拒绝和取消

- `POST /api/v1/tasks/{task_id}/confirm`：确认当前差异并请求合并。
- `POST /api/v1/tasks/{task_id}/reject`：拒绝变更，保留任务记录和补丁。
- `POST /api/v1/tasks/{task_id}/cancel`：取消尚未完成的执行。

所有写操作必须携带幂等键。重复确认不能产生第二次合并，重复取消不能使已完成任务回退。

## 8. 安全与隐私要求

- 所有浏览器到服务端的连接使用 HTTPS；本地开发可用明确提示的 HTTP 例外。
- 工作区授权、Agent 选择、工具调用和合并动作都必须可审计。
- 日志中禁止记录 API key、访问令牌、私钥、Cookie、原始音频和未经脱敏的环境变量。
- 用户请求文本可能包含代码和内部信息，服务端只在任务生命周期内按最小范围传递。
- Agent 的文件访问必须经过路径规范化和工作区边界检查，防止 `..`、符号链接和挂载路径绕过。
- 默认分支保护是服务端规则，不依赖网页按钮是否禁用。
- 断线、刷新或重复提交不能绕过确认步骤。

## 9. 可观测性与错误处理

每个任务至少关联：`session_id`、`task_id`、`workspace_id`、`agent`、`event_seq` 和 `trace_id`。日志应允许按任务回放以下事实：谁提交、使用哪个工作区、Agent 执行了哪些阶段、哪些文件变化、验证是否成功、谁确认了合并。

面向用户的错误按以下类别展示：

- `unauthorized`：未授权工作区或操作。
- `invalid_request`：需求、Agent 或状态不合法。
- `service_unavailable`：灵矽、MCP Server 或 Agent 不可用。
- `execution_failed`：Agent 或验证命令失败。
- `conflict`：工作区或目标分支发生冲突。
- `timeout`：任务超过服务端时间预算。

用户界面展示安全摘要，详细错误只写入受控日志，不直接透传底层命令输出或第三方凭据错误。

## 10. 验收标准

### 主链路

- 用户可以从手机或 Pad 打开网页，提交一条文字需求。
- 服务端创建唯一 `task_id`，页面能按顺序显示任务事件。
- Agent 只能在授权工作区和隔离变更集中工作。
- 页面能展示修改文件、diff、验证退出码和失败摘要。
- 用户未确认前默认分支不发生变化。
- 用户确认后只合并当前审查过的变更；成功后页面显示 `completed`。

### 异常链路

- 麦克风拒绝、浏览器不支持语音识别时，文字输入仍可完成任务。
- 页面断线重连后，能够从 `last_event_seq` 恢复，不重复显示或遗漏事件。
- Agent 超时或验证失败时，任务不会显示为成功，补丁和日志仍可查询。
- 重复点击确认、取消或刷新页面不会造成重复合并。
- 工作区路径越界、未知 Agent、过期会话和无权限操作均被服务端拒绝。

### 画面链路（后续验收）

- 网页观看和外部投屏可以独立开启和停止。
- 未授权用户无法观看指定工作区画面。
- 停止画面会话后，网页和外部接收端均停止接收新画面。

## 11. 实施顺序

1. 固化任务、状态、事件和 diff 数据结构，先用内存实现单任务流程。
2. 实现 MCP Server 工具注册、网页会话和 SSE 事件通道。
3. 接入一个本地 Agent，完成工作区隔离、补丁生成和固定验证命令。
4. 接入真实灵矽编排，并补充认证、授权、幂等和断线恢复。
5. 增加差异确认、合并失败恢复和审计查询。
6. 补充语音上传策略，再实现独立的画面观看和投屏链路。
7. 用端到端测试覆盖权限拒绝、取消、断线、验证失败和合并冲突。

## 12. 未决问题

- 灵矽的真实接入协议、会话生命周期和 MCP 注册方式是什么？
- 本地 Agent 使用何种进程接口和权限沙箱？
- 工作区授权由桌面端、MCP Server 还是一次性配对码完成？
- 合并目标是 Git 分支、补丁导出，还是由本地 IDE 执行？
- 验证命令由仓库配置声明，还是由服务端按项目类型选择？
- 任务和事件需要持久化多久，日志和音频是否允许本地保留？
- 画面采集源、编码格式、延迟目标和 AirPlay 兼容范围是什么？
